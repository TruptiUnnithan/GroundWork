# Groundwork agent for Microsoft 365 Copilot

A ramp-up coach for PMs in their first 90 days, built as a declarative agent in Copilot. It runs the task playbook, writes one-page briefs, debriefs meetings, decodes team terms, runs the Friday review and drafts Connects wins. It reads each PM's own OneDrive and SharePoint content, so every PM gets answers from their own work.

## What's here

| File | What it is |
| --- | --- |
| `instructions.md` | The agent's instructions. Edit this to change its behaviour. |
| `build.py` | Puts the instructions into the package, checks Copilot's limits and builds the zip. |
| `appPackage/manifest.json` | The app manifest that admins upload. |
| `appPackage/declarativeAgent.json` | Generated by `build.py`. Don't edit by hand. |
| `appPackage/color.png`, `outline.png` | Icons: 192×192 colour and 32×32 white outline. |
| `dist/groundwork-agent.zip` | The package to upload. |

## Rollout: pilot first, then all PMs

### 1. Pilot it yourself (today, no admin needed)

1. Open Microsoft 365 Copilot and choose **Create agent** (Agent Builder). Switch to the **Configure** tab.
2. **Name:** Groundwork. **Description:** Ramp-up coach for new PMs.
3. **Instructions:** paste the whole of `instructions.md`.
4. **Knowledge:** add your Loop workspace pages and the Groundwork spec, or leave it to search your OneDrive and SharePoint.
5. **Starter prompts:** copy the six from `build.py` (the `STARTERS` list).
6. Create it and use it for two weeks. Change `instructions.md` wherever it gets things wrong.

### 2. Share with a few PMs

From the agent's menu, share it with specific people or a group. Each person sees answers from their own content. Get feedback from two or three other new PMs before going wider.

### 3. Deploy to every PM (admin)

1. Run `python3 agent/build.py` to rebuild the zip after any change to the instructions.
2. Validate the package. Open the folder in VS Code with the **Microsoft 365 Agents Toolkit** extension and run its validation, or upload the zip in the Teams Developer Portal. Fix anything it flags.
3. Send `dist/groundwork-agent.zip` to your M365 admin with the request below.
4. The admin uploads it in the **Microsoft 365 admin center → Integrated apps** and assigns it to the PM security group. It then shows up in Copilot for everyone in that group.

To update it later, bump `version` in `manifest.json` (1.0.0 → 1.0.1), rebuild and send the new zip.

## Before you deploy

- **Replace the developer URLs** in `manifest.json` if this repo is private or moves. Admins check that the privacy and terms links open.
- **Check your org's process.** Many orgs require a privacy or responsible-AI review for agents, even instructions-only ones. Ask your admin which applies.
- **Schema versions.** The package uses declarative agent schema v1.0 and app manifest v1.19, which only allow knowledge from OneDrive and SharePoint. Newer schema versions add Teams messages, email and meetings as knowledge, which would let the agent read meeting recaps directly. The Agents Toolkit can upgrade the package. Until then, PMs paste the recap into the chat.

## Privacy

Groundwork has no backend and stores nothing. It runs inside Microsoft 365 Copilot under each user's own permissions and sees only content that user can already open. It never writes assessments of colleagues.

Provided as-is for internal use. Copilot output is a draft; confirm anything important with a person.
